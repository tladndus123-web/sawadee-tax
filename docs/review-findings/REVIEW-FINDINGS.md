- **시제품에서 그대로 이어진 문제:** 2, 3, 5, 6. 기존 동작을 충실히 옮겼다는 사실과 입력·검증의 정확성 문제는 별개다.

- 7번은 코드 경로 검토 결과다. 나머지 숫자·날짜 사례는 첨부한 자동 재현 테스트로 확인했고, 1·4번은 브라우저에서도 확인했다.

## 검수 순서별 결과

1. **시제품 이식:** 세금번호 체크섬, thaiInt/bahtText, 검사 키, 정규화 합계 보완의 핵심 구조는 일치한다. 방콕 날짜·영일 금액 숫자 표기·구조화된 번역 상세·위치 좌표는 안내서에 적힌 의도된 차이로 취급했다. 추가 ZIP의 시제품과 검수 ZIP 시제품은 동일하다.
2. **돈 계산:** 합계 누적과 합계 보완은 사탕 단위다. 품목 0.5바트·합계 1바트의 기존 테스트는 통과한다. 0원 검사 생략과 수량 정밀도 손실은 별도 문제다. `checks.ts:103`의 곱셈 및 `:116`~`:118`의 계산 흐름은 여전히 바트 부동소수점 연산 후 사탕으로 비교한다. “모든 연산이 사탕 정수”라는 설명은 엄밀히 맞지 않지만, 위 재현 외에 이 방식 자체의 오판을 별도 결함으로 단정하지 않았다.
3. **태국어 금액 경계값:** 기존 14개 금액 예시와 백만·백만+1·백만+11·백만+101·조 단위·사탕 경계 및 고정 시드 10,000개 입력, 총 10,014개를 시제품과 대조해 동일했다. 21·101·1,000,001의 `เอ็ด`, 0.50·11.25도 기존 테스트가 통과한다. 이는 제공된 시제품·예시와의 일치 검증이며 독립적인 태국어 언어 감수는 아니다.
4. **React/Next.js·화면:** Next.js 잠금 버전 15.5.26은 Next.js 15 요구와 맞는다. 타입 검사·ESLint 통과. 375px 보기·편집·지급 완료 선택·설정에서 문서 폭은 375px이었다. 품목 표 자체 스크롤과 1440px 다크 모드 캡처를 확인했다. 한국어·태국어·영어·일본어 문서 경로는 모두 HTTP 200 및 해당 html lang으로 열렸다. 입력마다 전체 normalize/runChecks를 다시 실행하는 구조는 있으나 문서 1장·최대 40품목에서 병목이라고 단정할 측정 근거는 없다. 필요할 때 profiler로 측정 후 최적화할 사항이다. Enter 제출은 실제 키보드 결함으로 기록했다. 전체 WCAG AA 적합성을 인증하는 검수는 수행하지 않았다.
5. **PROMPT 대비:** 7번 흐린 칸 표시 누락, 8번 회사 일치 정책을 기록했다. 문서에 미완료로 명시된 DB/RLS/로그인/초대/사진 업로드/AI 추출/장부/내보내기/대시보드/설치 README 등 5~9단계는 이번 완료 범위의 결함으로 중복 집계하지 않았다. localStorage 임시 설정, 관리자 제한 미구현, terms/formCode/formSince 편집 제외, 보기에서만 숨김, 회전 초기화, 샘플 중복 검사 데이터 없음도 알려진 제한으로 분리했다.
